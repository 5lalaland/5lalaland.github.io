2026-10-02｜DP、FL 与 Machine Unlearning：训练数据隐私保护的三条路径

一：隐私保护方法背景

训练一个模型时，数据可能来自用户的聊天记录、医疗记录、设备日志或企业内部文档。即使模型最终没有直接输出某条原始数据，训练过程仍然可能留下可被攻击利用的痕迹。

最典型的风险是 Membership Inference Attack（MIA，成员推断攻击）：

攻击者不一定要恢复完整数据，只要能够判断“某个人的数据是否参加过训练”，就可能已经泄露了敏感信息。

差分隐私（Differential Privacy，DP）、联邦学习（Federated Learning，FL）和机器遗忘（Machine Unlearning）经常一起出现，但三者解决的不是同一个问题：

方法 主要解决的问题 关键思路
Differential Privacy 训练过程中的个体贡献是否可被区分 限制单个样本对输出的影响，并加入随机噪声
Federated Learning 原始数据是否必须集中上传 数据留在本地，只上传模型更新或相关统计量
Machine Unlearning 已经参与训练的数据如何被删除 修改模型，使其尽量接近从未使用待删除数据重新训练的结果

可以把它们放在一条时间线上理解：

FL 改变数据如何参与训练，DP 限制训练中单个用户的影响，Machine Unlearning 处理训练完成后的删除请求。

二：Differential Privacy（差分隐私）

2.1 DP 保护的是什么？

设两个数据集只相差一个人的记录：

$$
D\sim D’
$$

一个随机算法 $\mathcal{M}$ 满足 $(\varepsilon,\delta)$-差分隐私，通常要求对任意输出集合 $S$ 都有：

$$
P[\mathcal{M}(D)\in S]
\leq e^\varepsilon P[\mathcal{M}(D’)\in S]+\delta
$$

直觉上，如果加入或删除某一个人的数据，算法输出的概率分布不会发生过于明显的变化，那么观察最终输出的人就很难判断这个人是否在数据集中。

这里的“隐私”不是让所有信息都消失，而是限制：

单个个体对发布结果的边际影响。

2.2 $\varepsilon$ 和 $\delta$ 是什么？

  • $\varepsilon$ 越小，两个相邻数据集的输出分布越接近，隐私保护通常越强；
  • $\delta$ 表示允许极小概率的额外失败事件，不能简单当成“隐私泄露比例”；
  • 多次训练、发布或查询会产生隐私预算消耗，需要进行组合分析。

因此，不能只说“使用了 DP，所以绝对不会泄露”。正确说法应该是：在给定隐私预算、机制和威胁模型下，个体参与对输出的影响被数学上限制。

2.3 DP-SGD 的基本做法

在深度学习中，常见方法是 DP-SGD。它对每个样本的梯度进行裁剪，再加入高斯噪声。

先限制单个样本梯度的范数：

$$
\bar g_i=g_i\cdot\min\left(1,\frac{C}{\lVert g_i\rVert_2}\right)
$$

其中 $C$ 是裁剪阈值。然后对裁剪后的梯度求和并加入噪声：

$$
\tilde g=\frac{1}{B}\left(\sum_{i=1}^{B}\bar g_i+\mathcal{N}(0,\sigma^2C^2I)\right)
$$

最后使用 $\tilde g$ 更新模型参数。

裁剪限制某一个样本的最大影响，噪声则掩盖精确的个体贡献。代价是模型训练可能更难收敛，最终任务性能也可能下降。

三：Federated Learning（联邦学习）

3.1 从集中式训练到联邦训练

传统集中式训练通常是：

$$
\text{用户数据}\rightarrow\text{中央服务器}\rightarrow\text{训练全局模型}
$$

联邦学习则把模型带到数据所在的位置：

  1. 中央服务器初始化全局模型 $M_t$；
  2. 选择一批客户端；
  3. 每个客户端在本地数据上训练若干步；
  4. 客户端上传模型更新，而不是上传原始数据；
  5. 服务器聚合更新，得到 $M_{t+1}$；
  6. 重复多个通信轮次。

最常见的 FedAvg 可以抽象为：

$$
M_{t+1}=\sum_{k=1}^{K}\frac{n_k}{\sum_j n_j}M_{t+1}^{(k)}
$$

其中 $n_k$ 表示第 $k$ 个客户端参与聚合的样本数量。

3.2 联邦学习的类型

类型 数据关系 例子
横向联邦学习（Horizontal FL） 不同参与方拥有相似特征空间，但样本不同 多家医院都有患者年龄、症状和检查结果
纵向联邦学习（Vertical FL） 不同参与方拥有相同或重叠用户，但特征互补 银行有收入信息，电商有消费信息
联邦迁移学习（Federated Transfer Learning） 样本和特征都不完全一致 不同领域之间迁移共享表示或模型能力

3.3 “数据不出本地”不等于自动安全

联邦学习减少了原始数据集中上传的需要，但上传的模型更新可能携带训练信息。攻击者可能通过：

  • 梯度反演（Gradient Inversion）重建输入特征；
  • 更新差分分析推断某个客户端是否参与；
  • 恶意客户端投毒模型或植入后门；
  • 服务器或其他参与方观察通信过程。

所以实际系统通常还需要结合：

  1. Secure Aggregation（安全聚合）：服务器只能看到聚合后的更新，不能直接看到单个客户端更新；
  2. Differential Privacy：对客户端更新或聚合结果加入噪声；
  3. 客户端认证与访问控制：限制谁能够加入训练；
  4. 异常更新检测：识别投毒、后门或异常梯度。

可以简单概括为：

FL 主要解决数据集中传输问题，DP 主要解决个体贡献可区分问题。二者可以组合，但互相不能替代。

四：Machine Unlearning（机器遗忘）

4.1 什么是机器遗忘？

假设原始训练集为：

$$
D=D_r\cup D_f
$$

其中 $D_f$ 是要求删除的 forget set，$D_r$ 是仍然需要保留的 retain set。原始模型为：

$$
M_o=\mathrm{Train}(D_r\cup D_f)
$$

最直接的删除方法是：删除 $D_f$，然后从头训练：

$$
M_{\mathrm{retrain}}=\mathrm{Train}(D_r)
$$

完整重训练通常可以作为机器遗忘的参考标准，但成本很高。Machine Unlearning 希望直接利用原模型和待删除数据得到：

$$
M_u=\mathrm{Unlearn}(M_o,D_f)
$$

并让：

$$
M_u\approx M_{\mathrm{retrain}}
$$

这里的“接近”不仅是参数距离接近，更重要的是模型行为、隐私攻击结果和保留任务能力接近。

4.2 为什么不能简单删除文件？

训练数据经过多轮梯度传播后，会对大量参数产生间接影响。即使把原始文件从数据库中删除，模型参数也不会自动恢复到“没有见过这些数据”的状态。

因此机器遗忘面对的是一个逆问题：

如何让模型减少对指定数据的记忆，同时尽量不破坏其他知识和任务能力？

4.3 两条基本路线

路线一：分块训练与局部重训练。

SISA（Sharded, Isolated, Sliced, and Aggregated）在训练前把数据分成多个 shard，并分别训练多个模型。删除某个样本时，只需要重新训练受影响的 shard，再重新聚合模型。

优点是删除成本低、过程容易解释；缺点是需要提前采用特殊训练架构，并且模型效果和存储成本可能受到影响。

路线二：直接修改模型参数。

一种直观方法是对 forget set 进行 Gradient Ascent：

普通训练希望最小化：

$$
\min_\theta L(D_f;\theta)
$$

遗忘时可以反向更新：

$$
\theta’ = \theta+\eta\nabla_\theta L(D_f;\theta)
$$

但只对 forget set 做反向更新，可能破坏正常能力。因此实际方法通常同时加入 retain loss：

$$
L_{\mathrm{unlearn}}
=-\lambda_fL(D_f;\theta)+\lambda_rL(D_r;\theta)
$$

它表达了两个目标：

$$
\boxed{\text{Forgetting}+\text{Utility Preservation}}
$$

五：DP、FL 与 Machine Unlearning 的关系

三者虽然都和隐私有关，但保护时点不同：

阶段 主要方法 主要问题
数据或用户参与训练前后 FL 原始数据是否必须集中到服务器
训练过程 DP 单个样本或用户的影响是否过于明显
模型已经训练完成之后 Machine Unlearning 已删除数据是否仍然残留在模型中

它们也可能形成组合方案：

$$
\text{本地数据}\xrightarrow{\text{FL}}\text{本地更新}
\xrightarrow{\text{DP}}\text{加噪更新}
\xrightarrow{\text{Secure Aggregation}}\text{全局模型}
$$

如果之后某个用户提出删除请求，还需要进一步判断：

  1. 该用户的数据是否确实参与过哪些训练轮次；
  2. 哪些客户端更新或模型分片受到影响；
  3. 是否可以执行局部重训练或参数遗忘；
  4. 遗忘后是否需要重新评估隐私和任务性能。

DP 可以降低单个样本留下明显记忆的概率，但它不等于对某个指定样本执行了删除。相反，Machine Unlearning 针对的是明确的 forget set，但如果系统没有保存训练记录，事后可能很难确定应该修改哪些组件。

六：怎样评估机器遗忘是否成功？

不能只看模型是否还能回答一句“我忘记了”。更合理的评估至少包括四类指标：

6.1 Forgetting Effectiveness

检查模型是否仍然能够逐字复现、准确回答或通过特定攻击恢复 forget set 内容。可以使用 MIA、数据提取测试和目标知识问答等方法。

6.2 Retain Utility

在 retain set 或正常任务上评估准确率、Loss、生成质量和安全性。理想的遗忘不应明显损害与删除目标无关的能力。

6.3 Generalization 与邻近知识

只让模型忘掉训练样本的原文可能不够。还需要检查相关事实、改写版本和上下文变体是否仍然以异常高的置信度保留，否则可能只是“忘记了表面字符串”。

6.4 Efficiency 与可扩展性

记录遗忘所需的时间、显存、额外存储和重复删除成本。一次删除很快但无法处理连续请求的方法，未必适合真实系统。

Google Research 的 MUSE 评估思路把好的 LLM unlearning 系统拆成多个目标：不再逐字复现 forget data、不再保留相关知识、降低隐私泄露、保持 retain 能力、支持大规模删除，以及能够处理连续多次删除请求。单一指标变好，并不代表整个遗忘系统已经可靠。

九：自测题

1. Federated Learning（FL）和 Differential Privacy（DP）分别解决什么问题？为什么使用了联邦学习仍然可能遭受隐私攻击？
答：Federated Learning（联邦学习）主要解决数据分散存储、难以集中训练的问题，其核心思想是让多个客户端在本地使用各自的数据训练模型，再将模型参数或梯度更新上传到服务器进行聚合，从而减少直接集中收集原始数据的需求。而 Differential Privacy（差分隐私）主要解决训练数据中的个体信息可能通过模型或统计结果泄露的问题，通过限制单个样本或用户对输出分布的影响，降低攻击者推断其是否参与训练的能力。两者的区别在于，FL 主要改变数据的训练与存储方式，DP 则提供一种可量化的隐私保护机制。需要注意，FL 并不天然保证隐私，因为梯度或模型更新仍可能携带训练数据的信息，攻击者可能利用 Gradient Inversion 重建部分输入，或者通过 Membership Inference 推断成员身份。因此实际系统可能结合 FL、Secure Aggregation（安全聚合）和 DP，分别解决分布式训练、聚合更新保密和个体隐私保护等不同问题。

2. Differential Privacy 为什么能够防御 Membership Inference Attack？DP-SGD 是如何实现差分隐私的？它是否意味着 MIA 完全失效？
答：差分隐私的核心思想是，对于两个仅相差一个个体数据的相邻数据集，算法产生某个输出的概率应当足够接近，从而限制攻击者通过观察模型判断该个体是否参与训练。DP 通常通过 ε（隐私预算）和 δ（允许的微小松弛概率）描述隐私保证，一般来说，在其他条件相同且 δ 足够小的情况下，ε 越小意味着保护越强。DP-SGD 是深度学习中实现差分隐私的经典方法，主要包括三个步骤：首先计算每个样本的梯度，其次通过 Gradient Clipping（梯度裁剪）限制单个样本梯度的贡献，最后在聚合梯度中加入经过校准的高斯噪声，再执行参数更新。梯度裁剪限制了单个样本的影响范围，而加入噪声使模型更新难以精确反映某个样本是否存在，从而限制成员推断优势。但是 DP 并不意味着 MIA 完全失效，它只是提供有条件、可量化的隐私保证，具体风险仍取决于 ε、δ、隐私保护单位、训练过程和攻击者掌握的先验信息。对于 LLM，DP 训练还可能带来模型性能下降和额外计算开销，因此需要权衡 Privacy 与 Utility。

3. 为什么 Machine Unlearning 不能简单理解为删除训练文件？Exact Unlearning 和 Approximate Unlearning 有什么区别？
答：因为模型在训练过程中已经通过梯度下降将训练数据的信息编码进模型参数，即使删除原始文件，数据对模型参数和输出行为的影响也不会自动消失。例如某个语言模型使用包含敏感个人信息的数据进行训练，之后直接从训练集中删除这些记录，但模型仍可能复现相关信息。Machine Unlearning（机器遗忘）的目标是消除或尽可能减小指定 Forget Set 对已训练模型的影响，使遗忘后的模型接近仅使用 Retain Set 重新训练得到的模型。Exact Unlearning 要求遗忘结果满足与从头重训练相应的精确等价条件，通常涉及严格的算法或模型分布保证；Approximate Unlearning 则允许遗忘后的模型与重训练参考模型存在一定差异，以降低计算成本。对于大型语言模型，完全重新训练的代价可能非常高，因此研究中经常使用近似遗忘方法，例如基于梯度更新、模型编辑、知识蒸馏或参数高效调整的方法。但需要注意，模型不再回答某个问题，不代表它已经真正消除了相关训练信息。

4. 为什么 Machine Unlearning 中经常使用 Gradient Ascent？为什么不能只对 Forget Set 执行 Gradient Ascent，而需要结合 Retain Loss？
答：普通模型训练采用 Gradient Descent（梯度下降），通过最小化训练 Loss 使模型更好地拟合训练数据；Gradient Ascent（梯度上升）则反过来增大指定样本上的 Loss，试图削弱模型对 Forget Set 的拟合程度，因此可以用于某些近似机器遗忘方法。但是如果只对 Forget Set 持续执行 Gradient Ascent，模型可能出现参数更新过大、正常知识受损和任务能力下降等问题，因为语言模型的参数通常同时服务于大量不同知识和任务，忘记某部分数据时也可能影响其他数据。因此一种常见思路是在提高 Forget Loss 的同时最小化 Retain Loss，让模型降低对需要遗忘数据的拟合程度，同时尽可能保持对保留数据的正常预测能力，可以理解为同时优化两个目标：Forget Set 上尽量减少需要删除的信息影响，Retain Set 上尽量维持原有性能。但这一过程存在 Privacy-Utility Trade-off（隐私与效用权衡），而且单纯提高 Forget Loss 并不能保证真正完成遗忘，因为模型仍可能通过改写提示、其他上下文或不同攻击方法暴露相关信息。

5. 如果某个 Unlearning 方法让 Forget Set 的 Loss 明显升高，MIA 的 AUC 下降到 0.5，是否可以认为遗忘已经成功？应该如何设计完整的 Unlearning Evaluation？

答：不能直接认定成功。Forget Loss 升高只能说明模型对指定样本的预测能力下降，而 MIA AUC 接近 0.5 只说明当前攻击方法在当前评估分布下接近随机区分水平，并不能证明所有成员信息都已经消除，更不能证明模型与 Retrain-from-scratch 参考模型等价。例如某种遗忘方法可能只是人为提高 Forget Set 的 Loss，从而使基于 Loss 的 MIA 失效，但其他基于生成概率、模型行为差异或特定提示的攻击仍可能检测到残留信息。因此完整的 Unlearning Evaluation 至少包括四个方面：① Forgetting Efficacy，检查 Forget Set 上的 Loss、MIA、敏感内容复现率和改写提示下的泄露情况；② Model Utility，检查 Retain Set 和独立测试集上的任务性能，避免通过破坏整个模型实现表面遗忘；③ Retraining Comparison，将遗忘模型与仅使用 Retain Set 从头训练的参考模型比较，分析输出行为和隐私风险的差异；④ Efficiency and Robustness，评估遗忘时间、计算成本、连续删除请求以及不同攻击方法下的表现。尤其需要注意，MIA 结果受到成员与非成员分布、阈值校准和攻击器强度影响，因此仅报告一个 AUC 并不足以证明遗忘有效。
6. Differential Privacy 和 Machine Unlearning 都能降低隐私风险，那么为什么还需要 Machine Unlearning？二者能否结合？遗忘操作本身有没有可能引入新的隐私风险？

答：DP 和 Machine Unlearning 的区别主要在保护阶段与目标不同。DP 通常在训练或数据处理阶段限制单个个体对模型输出的影响，目的是从机制上降低其数据是否参与训练所造成的可观察差异；Machine Unlearning 则主要针对已经完成训练的模型，在收到删除请求后尝试消除特定数据对模型的影响。即使模型使用 DP 训练，也不意味着任何隐私预算下都能满足后续删除请求所要求的遗忘标准，因此两者不能简单互相替代。它们可以结合，例如在训练阶段使用 DP 限制个体贡献，在删除阶段执行 Machine Unlearning，但需要进一步分析组合机制的隐私保证和模型效用。特别值得注意的是，Machine Unlearning 本身也可能产生新的隐私风险：如果攻击者能够同时访问遗忘前后的模型，就可能利用两者输出概率或模型参数变化构建新的 Membership Signal，推断哪些样本受到了删除操作影响。这也是《When Machine Unlearning Jeopardizes Privacy》所强调的重要问题之一。因此遗忘并不天然等于隐私增强，评估时不仅要关注遗忘后的模型是否还记得某条数据，还要考虑遗忘前后模型差异是否暴露新的成员身份信息，以及攻击者能够观察哪些模型版本。
