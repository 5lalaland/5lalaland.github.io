1. AI 安全常用术语

1 Meta（元 / 元学习）

定义： Meta 表示“更高层次的”或“关于某事物本身的”。在机器学习中，Meta-learning（元学习）指让模型学会如何学习，从而快速适应新任务。

作用： 提高模型面对新任务、新数据或未知攻击时的适应能力。

例子： MAML（2017）是一种经典元学习方法，使模型能够利用少量样本和少数梯度更新快速适应新任务。

常见相关概念： Meta-analysis（元分析）、Metadata（元数据）、Meta-evaluation（元评估）。Meta 不一定指元学习，具体含义取决于上下文。

2 TF-IDF（词频-逆文档频率）

定义： TF-IDF 是一种衡量词语在文档中重要程度的统计方法。一个词在当前文档中出现得越频繁，同时在其他文档中越少见，通常权重就越高。

计算公式：

$[ TF\text{-}IDF(t,d)=TF(t,d)\times IDF(t) ]$

作用： 用于关键词提取、文本检索、文本分类和相似度计算。

例子： 在恶意提示词检测中，通过 TF-IDF 将输入文本转换为特征向量，再使用 SVM 等分类器识别恶意输入。

相关概念： Embedding（嵌入向量）。TF-IDF 主要关注词频统计，Embedding 则可以学习语义信息。

3 Interpretability（可解释性）

定义： 指理解 AI 模型如何作出决策，以及模型内部特征、参数或计算机制如何影响输出结果的能力。

作用： 帮助研究人员理解模型行为、发现潜在偏差、分析安全漏洞和定位错误原因。

例子： Anthropic 的 Towards Monosemanticity（2023）通过稀疏自编码器研究神经网络内部的可解释特征。

相关概念： Explainability（可解释说明）更强调解释某次输出的原因；Interpretability 更强调理解模型行为或内部机制，两者经常交叉使用。

4 Audit / AI Auditing（人工智能审计）

定义： 对 AI 系统的数据、模型行为、开发流程、安全风险和合规情况进行系统性检查与评估。

作用： 发现模型潜在的安全漏洞、算法偏见、隐私泄露风险以及不符合预期的行为。

例子： Gender Shades（2018）对商业人脸性别分类系统进行评估，发现系统在不同肤色与性别群体之间存在明显的准确率差异。

相关概念： Evaluation（评估）侧重性能测量；Red Teaming（红队测试）侧重主动寻找漏洞；Auditing 则是更全面的系统性检查。

5 Alignment（对齐）

定义： 使 AI 模型的行为尽可能符合人类意图、预期目标、价值要求和安全约束。

作用： 减少模型产生不符合预期或有害行为的可能性，提高模型的有用性与安全性。

例子： InstructGPT（2022）通过监督微调和 RLHF（人类反馈强化学习），让语言模型更好地遵循用户指令。

相关概念： Safety（安全性）强调避免或降低危害；Alignment 强调模型行为与预期目标的一致性，两者密切相关但不完全相同。

6 Trustworthy AI（可信人工智能）

定义： 指在可靠性、安全性、隐私保护、公平性、透明度和可解释性等方面具有可信特征的人工智能系统。

作用： 确保 AI 不仅具有较好的任务性能，还能够在实际应用中保持可靠、可控并受到适当监督。

例子： NIST AI Risk Management Framework（AI 风险管理框架）提出了一套用于识别、评估和管理 AI 风险的方法。

相关概念： Trustworthy AI 是综合性的系统目标，而 Robustness、Interpretability、Privacy 等是其重要组成部分。

7 Threat Modeling（威胁建模）

定义： 在安全研究中，系统性分析潜在攻击者的目标、能力、知识范围、攻击入口及可能造成的安全风险。

核心要素： Attacker（攻击者）、Attacker Goal（攻击目标）、Attacker Capability（攻击能力）、Attack Surface（攻击面）、Trust Boundary（信任边界）。

作用： 明确攻击在什么条件下能够发生，并判断攻击场景是否合理、攻击结果是否具有现实意义。

例子： 在 RAG 提示注入攻击中，研究者可能假设攻击者只能修改外部知识库中的部分文档，不能直接修改模型参数或系统提示词。

相关概念： Threat Model 描述攻击条件和假设；Attack Method 描述具体采用的攻击技术。

8 Model Inversion（模型反演攻击）

定义： 攻击者利用模型输出、置信度或其他可获得的信息，尝试反推出模型输入的敏感特征或相关数据。

作用： 主要用于研究机器学习模型是否存在隐私泄露风险。

例子： Fredrikson 等人在 CCS 2015 的论文 Model Inversion Attacks that Exploit Confidence Information and Basic Countermeasures 中，研究了利用模型置信度信息重建可识别人脸特征的攻击。

相关概念： Membership Inference（成员推断）判断某条数据是否属于训练集；Model Inversion 则侧重恢复或推断敏感信息。

9 Recall（召回率）

定义： 在所有实际属于正类的样本中，被模型成功识别为正类的比例。在安全检测中，通常表示真正存在的攻击有多少被检测出来。

计算公式：

$[ Recall=\frac{TP}{TP+FN} ]$

其中，TP 表示真正例，FN 表示假负例（漏检）。

作用： 评估检测系统发现攻击、异常行为或其他目标样本的能力。

例子： 测试集中有 100 条恶意提示词，检测器成功识别 90 条，漏掉 10 条，则 Recall = 90%。

相关概念： Precision（精确率）关注检测出来的样本有多少是真的；Recall 关注实际存在的目标样本有多少被检测出来；F1-score 则综合两者进行评价。

2. AI 推理阶段知识补充

2.1 推理阶段（Inference）

定义： 推理阶段是指模型完成训练后，接收输入并通过前向计算生成预测结果或文本的过程。对于大语言模型（LLM），通常采用自回归方式逐个生成 Token。
目标： 在保证输出质量与安全性的前提下，降低推理延迟、提高吞吐量，并减少 GPU 显存和计算资源开销。

2.2 推理流程

基本流程： 输入构建与分词 → Embedding → Prefill → Transformer → Logits → Token 采样 → Decode → 输出。

  • Embedding（嵌入）： 将 Token ID 转换为向量表示，并结合位置信息。

  • Transformer： 模型的核心网络结构，通过注意力机制和前馈网络提取上下文信息。

  • Prefill（预填充）： 一次处理已有的输入序列，计算隐藏状态以及各层的 Key、Value，为后续生成做准备。

  • Decode（解码）： 根据已有上下文预测下一个 Token，并将新 Token 加入序列，重复这一过程直到满足停止条件。

2.3 QKV（Query、Key、Value）

定义： Q、K、V 是 Transformer 自注意力机制中的三个关键向量，分别表示查询、键和值。
$$Q=XW_Q,\quad K=XW_K,\quad V=XW_V$$
其中，(X) 为输入隐藏状态，(W_Q)、(W_K)、(W_V) 为可学习的投影矩阵。
核心原理： Q 与 K 计算注意力权重，V 提供被加权聚合的信息。典型的缩放点积注意力公式为：
$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V$$
其中，(d_k) 为 Key 的维度，(M) 为注意力掩码。在自回归模型中，因果掩码用于防止当前位置访问未来 Token。

2.4 KV Cache（键值缓存）

定义： 缓存历史 Token 在 Transformer 各层计算得到的 K、V，避免生成新 Token 时重复计算历史位置的 K、V。
作用： 减少重复计算，提高自回归解码效率。
局限： KV Cache 会占用显存，其开销通常随上下文长度、批次大小、模型层数和 KV 头数增加。因此，长上下文和高并发场景需要优化缓存管理。

2.5 Prompt Cache（提示词缓存）

定义： 缓存提示词相关的计算结果，使后续请求能够复用已有计算，减少重复处理输入的开销。在许多推理系统中，这通常通过 Prefix Cache（前缀缓存）实现，即复用相同输入前缀对应的 KV 状态。
例子： 多个请求具有相同的系统提示词，但用户问题不同。系统可以在缓存有效且匹配条件满足时，复用共同前缀的计算结果，减少 Prefill 开销。
与 KV Cache 的区别： KV Cache 通常用于同一请求的自回归解码，复用历史 Token 的 K、V；Prefix Cache 则进一步支持不同请求之间复用共同前缀的计算结果。两者相关，但不是完全相同的概念。Prompt Cache 的具体含义可能随推理框架而变化。

2.6 推理性能优化技术

  • KV Cache： 减少历史 Token 的重复计算。

  • Prefix Cache： 复用相同提示词前缀的计算结果。

  • Continuous Batching（连续批处理）： 动态调度请求，提高 GPU 利用率与吞吐量。

  • PagedAttention： 优化 KV Cache 的显存分配与管理。

  • FlashAttention： 优化注意力计算及显存访问效率。

  • Quantization（量化）： 使用较低精度表示模型权重或计算数据，降低显存占用。

  • Speculative Decoding（推测解码）： 先由辅助模型生成候选 Token，再由目标模型验证，以加速生成。

2.7 推理性能指标

  • TTFT（Time to First Token）： 从请求开始到生成第一个输出 Token 的时间。

  • TPOT（Time Per Output Token）： 平均每个输出 Token 的生成时间，具体统计口径需根据评估方法确定。

  • Throughput（吞吐量）： 单位时间内处理的请求数或生成的 Token 数。

  • Memory Footprint（内存占用）： 模型权重、KV Cache 及其他运行时数据占用的内存。

总结： Prefill 和 Decode 是推理的两个主要计算阶段；QKV 是注意力机制的组成部分；KV Cache 与 Prompt Cache 是用于减少重复计算的缓存机制。推理优化的核心是在保证模型质量与安全性的前提下，提高生成速度、吞吐量和资源利用率。
