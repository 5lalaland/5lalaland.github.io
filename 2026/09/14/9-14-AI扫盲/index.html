MCP Server（文件、数据库、API、计算器）

MCP:模型上下文协议，用来让 Agent 标准化调用外部工具 / 服务。

  • 写一次 MCP Server，任何支持 MCP 的 Agent（LangChain、Claude Desktop、Cursor）都可以直接调用；

  • 工具能力自动发现，不用硬编码工具列表；

  • 统一权限边界，隔离外部系统，方便管控安全。
    不负责思考推理，只管 Agent 和外部工具之间的标准化通信。

  • Host（AI 应用 / Agent）：用于协调和管理一个或多个 MCP 客户端的 AI 应用程序

  • MCP Client ：一个维护与 MCP 服务器连接并从 MCP 服务器获取上下文以供 MCP 主机使用的组件。

  • MCP Server：一个为 MCP 客户端提供上下文信息的程序

Agent:根据信息进行推理/规划并采取行动的AI智能系统
组件：

  • 大脑：LLM:chatpgt,qwen等
  • 记忆：大模型记住之前的聊天和操作，利用背景和上下文
  • 工具：互动的主要方式
    1. 主动获取上下文信息：检索数据并搜集文档
    2. 采取行动：收发邮件，增删数据库
    3. 编排：调用其他代理，触发工作流
      大部分是单agent 也可以用多Agent
  • API = 两个程序交流的接口：定义与规定了可以发送什么请求并且获得什么数据
    常用Get/Post方式，采用json格式
    https://example.com/api/chat 是 API 地址
    sk-xxxxxxxx是 API Key，证明我有权限调用这个 API
东西 例子 作用
API地址 https://xxx.com/api/chat 去哪里调用
API Key sk-xxxx 证明身份
Token eyJxxx 登录凭证
参数 {“message”:”hello”} 发送的数据

搭建agent平台:n8n

LangChain:开源的python AI应用开发框架，提供了摸快和工具
功能：

  • 统一接口：管理LLM和prompt
  • chain：智能流水线，把多个组件链接起来
  • LCEL：灵活自定义整个AI任务的处理流程
  • RAG:检索增强，全套工具
  • agent：LLM为核心的决策引擎
  • memory：让大模型记住部分对话

组成：

  1. langchain libraries:提供多个包，框架清晰
  2. langchain templates:langchain 提供的官方模版
  3. langchain serve :基于fastapi将langchain的链发布为rest api
  4. langsmith:开发平台，适合debug

1预处理阶段：文本->分词token
数据来源：common crawl
词语->UTF编码(01)->8位一组十进制->116,32这种常见的合并
训练：神经网络，根据前面的token预测后面的词元 现代参数量接近1万亿 上下文几十万
16亿->1天600美元

预处理阶段->自回归模型，autoregressive (AR)模型，只负责根据前面的token预测后面的内容，无对话功能

2.后训练阶段 post-training
SFT监督 微调
训练时间远小于预训练，学习对话

hallucination解决
找到ai的知识边界，将知识边界外的问题设置为我不知道并放入训练集；评估置信度
推理好过直接给答案

3.RL强化学习（后训练的一种）
预训练->读书获得背景信息
后训练->学习专家的解题办法
强化学习->找到例题的最优解
我们和llm的理解方式不同，人工标注的数据集并不一定是llm最易于理解的方式

1.SFT ->
2.训练奖励模型 RM（Reward Model）【离线】

  1. 拿同一个 prompt，让 SFT 模型采样多条不同回答
  2. 交给人类标注员，对多条回答做排序：哪个更好、哪个更差
  3. 训练一个奖励模型：输入prompt+回答，输出一个标量分数，代表这个回答有多好
    3.PPO 强化学习在线优化【真正的 RL 循环】
  4. Rollout（在线采样）：当前策略模型（Policy）接收 prompt，自己生成回答（包含完整思维链）
  5. 打分：把生成的prompt+模型输出送入奖励模型 RM，得到奖励 r；额外加上KL 惩罚项> KL 惩罚：约束新模型输出不能和原始 SFT 模型差太远，防止模型乱编、奖励黑客、语言崩坏
  6. 更新策略（PPO）：最大化期望奖励，更新大模型权重；PPO 会限制策略更新幅度，避免一次更新过大
  7. 循环：回到 Rollout，不断生成新回答、打分、更新，直到收敛

带来“神之一手”和“顿悟时刻”
奶酪漏洞：ndrej Karpathy 提出的，专门用来描述大语言模型能力的特点，也就是写的 Swiss cheese model of LLM capabilities。

瑞士奶酪（埃曼塔奶酪）本身有很多随机孔洞，用它比喻大模型： ✅ 奶酪实体部分：模型做得很好的能力； 🕳️ 奶酪上的孔洞：模型莫名其妙会翻车、做不好的能力（也就是 “漏洞”）。

PPO：近端策略优化：

  • Clip 裁剪：限制每一轮策略更新的幅度，不让新模型和上一轮差距太大，避免训练崩坏。
  • KL 散度惩罚：额外加一个惩罚项，约束当前策略模型与初始 SFT 模型的输出分布差异，防止模型为了拿高分彻底偏离正常语言、编造事实。
    RLHF：目前大语言模型对齐人类偏好的经典方案，目标是让模型输出不仅正确，还符合人类对 “有用、无害、清晰、有条理” 的主观期待。
  1. SFT 监督微调：用人工撰写的「指令 - 高质量回答」成对数据，先把基座模型调教成能听懂指令的基础助手模型。
  2. 奖励模型（RM）训练：同一个 prompt 让 SFT 模型生成多条回答，由人类标注员按偏好排序，用排序数据训练一个奖励模型，输入「问题 + 回答」输出一个代表质量的分数。
  3. 强化学习优化：用 PPO 算法，让策略模型不断生成回答，从 RM 获取分数作为奖励，迭代更新模型权重，最大化预期得分。
    . RLVR：可验证奖励强化学习：奖励不来自人类主观打分，而来自程序自动验证的客观结果。
