1. RAG 原理

准备：切片->索引
回答：召回-重排-生成

  1. 切片：按照字数，段落…..方式分

  2. 索引：embedding将文本转换成向量
    再将向量存储在向量数据库（原文和向量）当中

  3. 召回：返回与用户问题向量相似度最高的topk个文段；目前根据欧氏距离，点积,cos相似度等 成本低但准确率低

  4. 重排：返回用cross-encoder计算出的刚刚的topk个文段中更相近的几个文段

  5. 生成：AI根据文段生成结果

1.1 自测题

1. 为什么RAG比普通LLM更容易受到数据投毒？

RAG系统容易受到投毒攻击的主要原因是它引入了外部知识源，而这些数据通常被模型默认认为具有一定可信度。传统LLM主要依赖训练阶段固定的参数知识，而RAG系统会实时检索外部文档并拼接到Prompt中，因此攻击者可以通过影响检索结果间接影响模型输出。此外，向量数据库通常根据语义相似度进行检索，而不是根据真实性进行判断，因此攻击者可以构造与目标查询高度相关的恶意文档，提高其被召回的概率。同时，LLM本身缺乏可靠的事实验证能力，当恶意文档进入上下文后，模型可能会将其作为可信信息进行总结和生成。因此RAG系统需要额外考虑数据可信度、来源验证以及检索安全。

2. 什么是Embedding Poisoning？

Embedding Poisoning是针对RAG检索阶段的一种攻击方式，攻击者通过修改文档内容或者优化文档表示，使恶意文档在向量空间中更容易匹配用户查询，从而提高被检索到的概率。RAG系统通常会将文档转换成Embedding向量，然后根据向量相似度进行召回，因此攻击者可以利用Embedding模型的语义表示特点，让恶意文档在向量空间中靠近目标查询。与普通文档投毒相比，Embedding Poisoning更加关注检索过程，而不仅仅是文档内容本身。防御这种攻击需要结合异常向量检测、检索结果验证、多模型交叉检查以及可信数据源管理。

3. RAG系统为什么会发生越权访问？

RAG越权访问主要是由于检索层和权限控制层没有进行绑定。很多RAG系统只关注语义相关性，而忽略用户身份权限。例如用户A查询问题时，系统根据Embedding相似度直接返回Top-K文档，但没有检查这些文档是否属于用户A可访问范围，导致用户可能通过构造查询获取本不应该看到的信息。

4. RAG中的Embedding有哪些方法？

RAG向量化的核心是使用Embedding模型将文本转换为高维向量，使语义相似的文本在向量空间中距离更近。常见方法包括基于Transformer的Embedding模型，例如OpenAI Embedding模型、BERT类模型，以及开源模型如BGE、E5、GTE等。实际系统通常采用Chunk级Embedding，因为完整文档过长会降低检索精度。

5. RAG检索有哪些方法？

RAG检索主要分为稠密检索、稀疏检索和混合检索。稠密检索通过Embedding计算语义相似度，例如Cosine Similarity，可以找到语义相关但关键词不同的文档；稀疏检索主要基于关键词匹配，例如BM25，更适合精确查询；混合检索则结合两者优势，提高召回率。此外，现代RAG系统还会加入Reranker模型，对初步召回结果进行二次排序，提高最终提供给LLM上下文的质量。

6. RAG中的Chunk是什么？为什么需要Chunk？

Chunk是RAG系统中将长文档切分成多个较小文本片段的过程。由于大语言模型存在上下文窗口限制，同时检索系统需要精确定位相关信息，因此不能直接将完整文档输入模型，而需要先将文档拆分成多个语义单元，再分别进行Embedding并存入向量数据库。当用户查询时，系统通过向量相似度检索最相关的Chunk，并将这些片段作为上下文提供给LLM生成答案。Chunk划分的目标是在保持语义完整性的同时，提高检索准确率。

2. RAG 投毒

2.1 知识库投毒（Knowledge Base Poisoning）

攻击者向 RAG 知识库中植入恶意内容，使其在后续检索和生成过程中影响模型输出。

  • 直接投毒：直接上传包含错误信息或恶意指令的文档。
  • 嵌入对齐攻击：构造文档，使其在嵌入空间中与目标查询高度相似，从而提高被检索到的概率。
  • 靶向投毒：针对某个特定查询优化恶意文档，只在目标问题出现时触发攻击。
  • Poisoned-RA：同时满足两个条件：
    • 检索条件（Retrieval Condition）：恶意文本与目标问题在嵌入空间中足够接近，能够进入 Top-k 检索结果；
    • 生成条件（Generation Condition）：恶意文本被加入上下文后，能够诱导 LLM 输出攻击者预设的内容。

2.2 检索结果操纵（Retrieval Manipulation）

攻击者不一定直接修改模型，而是通过操纵检索排序，让恶意内容更容易排在正常文档之前。
常见方式包括：

  • 关键词堆叠：大量加入与目标查询相关的关键词，提高检索排名；
  • 元数据利用：伪造或操纵标题、标签、时间、来源等元数据，提高文档的检索优先级。

2.3 向量数据库攻击（Vector Database Attacks）

攻击者直接针对向量数据库，例如通过未授权访问、数据篡改或恶意向量插入，影响知识库中的 Embedding 和检索结果。

2.4 上下文窗口攻击（Context Injection）

RAG 会将检索到的文档加入 LLM 的上下文窗口。攻击者可以利用这一机制，在文档中植入恶意指令，使模型把“不可信文档内容”误认为系统指令，从而影响最终生成结果。

2.5 RAG 安全防护

防护可以按照 RAG 的处理流程分层进行：
知识库摄入层

  1. 验证文档来源和上传者身份；
  2. 扫描恶意内容和隐藏指令；
  3. 过滤敏感信息；
  4. 高风险文档审核后再入库。

检索层

  • 来源可信度标记：对不同来源设置可信等级；

  • 相似度阈值：过滤相关性过低的文档；

  • 检索多样性控制：避免单一文档或单一来源主导 Top-k；

  • 异常检索检测：识别异常查询和异常文档召回模式。
    生成层

  • 明确区分“系统指令”和“检索到的外部数据”，避免模型直接执行文档中的指令；

  • 对最终生成结果进行安全检查和敏感信息过滤。

2.6 自测题

1. 什么是 Embedding 对齐攻击

Embedding 对齐攻击的核心思想是，攻击者不只是让恶意文档在文字表面看起来相关，而是让它在向量空间中尽可能接近目标查询。RAG 检索通常会把用户 Query 和知识库中的 Chunk 都转换成向量，然后根据余弦相似度或者其他距离度量选出 Top-k。因此攻击者可以构造一些包含目标关键词、语义改写或者特定文本模式的恶意 Chunk，使其 Embedding 与目标问题高度相似。这样即使恶意内容本身质量很差，也可能在检索排名中超过正常文档。它说明 RAG 的攻击目标并不一定是 LLM 本身，也可以是前面的向量检索机制。

2. 关键词堆叠和 Embedding 攻击有什么区别

关键词堆叠主要利用传统检索或者混合检索中的关键词匹配机制，比如在恶意文档中重复加入用户可能搜索的关键词，从而提高 BM25 或搜索引擎排名；而 Embedding 攻击针对的是语义向量检索，它通过修改文本语义，让恶意文档的向量与目标 Query 的向量更加接近。两者攻击的层面不同，但在实际 RAG 中往往可以组合使用，因为很多系统采用 Hybrid Search，也就是同时使用关键词检索和向量检索。因此更现实的攻击者可能同时优化关键词匹配分数和向量相似度，以提高恶意文档进入 Top-k 的概率。

3. 相似度阈值能不能完全防止 RAG 投毒

不能。相似度阈值只能过滤与用户问题明显无关的文档，但很多投毒攻击本身就是专门优化相似度的。攻击者甚至可能让恶意文档与目标问题比正常文档更加相似，这时提高阈值不仅无法阻止攻击，反而可能把一些正常文档过滤掉。因此相似度阈值更适合作为基础防御措施，而不能单独使用。更完整的方法应该同时考虑来源可信度、内容安全扫描、检索多样性、异常检测、Reranker、安全上下文构造以及生成后的输出检查。

4. 为什么检索多样性可以缓解数据投毒

如果 Top-k 全部来自同一个文档、同一个网站或者同一个上传者，那么攻击者只要控制这一个来源，就可能完全控制模型的上下文。检索多样性控制会限制单一来源占据过多检索结果，例如 Top-5 中最多允许两个 Chunk 来自同一文档，同时优先选择不同来源但语义一致的证据。这样即使一个恶意文档排名很高，也很难完全主导上下文，而且模型还可以通过多个独立来源进行交叉验证。因此多样性防御并不能保证完全阻止投毒，但可以显著提高攻击者需要控制的数据量和攻击成本。

5. 为什么 RAG 防御需要做来源可信度控制？

因为单纯的语义相关性并不等于可信度。一个恶意文档完全可以和用户问题高度相关，但内容本身是错误或者恶意的。如果 Retriever 只按照相似度排名，就可能把攻击者生成的文档排在官方文档之前。因此实际系统可以同时维护 relevance score 和 trust score，例如官方文档、内部数据库和经过审核的数据源具有更高可信度，而匿名上传内容或者互联网抓取内容具有较低可信度。最终检索排序不仅考虑“这个文档和问题有多相关”，还考虑“这个文档有多可信”，从而降低单一恶意数据源控制回答的风险。

6. 如果你来设计一个安全的 RAG 系统，会在哪些位置做防御

我会按照 RAG 的数据流进行分层防御。首先在知识库摄入阶段验证上传者和数据来源，并扫描隐藏指令、异常文本以及敏感信息；其次在 Embedding 和向量数据库阶段限制写权限，监控异常批量插入和异常向量分布；在检索阶段结合相似度、来源可信度和检索多样性，并使用 Reranker 再次验证结果；在上下文构造阶段明确告诉模型“检索内容是数据而不是指令”，避免执行文档中的命令；最后在生成阶段进行事实一致性、敏感信息和异常输出检查。核心思想不是依赖单一防御，而是让攻击者必须同时突破多个层次。
