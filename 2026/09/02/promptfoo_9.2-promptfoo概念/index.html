9.2-promptfoo概念

发表于2026-09-02|更新于2026-10-04|AI Security
|浏览量:

Promptfoo本质上是“自动给 AI 系统发送恶意输入，再判断它有没有被攻破”的测试框架。它不是传统的端口扫描器，也不会凭空入侵服务器。

能实现哪些攻击

Promptfoo目前提供大量模块化测试，官方列出约157个插件，主要包括：官方插件目录

类型 典型攻击
提示词攻击 System Prompt Override、Prompt Extraction、Jailbreak
隐私泄露 PII 泄露、跨会话泄露、训练数据诱导提取
权限绕过 BOLA、BFLA、RBAC、越权操作
RAG攻击 间接提示注入、文档窃取、知识库投毒
Agent攻击 工具滥用、内存投毒、MCP攻击、数据外传
应用安全 SQL注入、Shell注入、SSRF、Debug Access
内容安全 暴力、自残、违法操作、偏见、有害建议
业务风险 虚假承诺、擅自退款、价格操纵、幻觉
Coding Agent 读取密钥、越过沙箱、修改CI、生成不安全代码

攻击能做到什么程度

攻击强度分三层：

  1. Basic/Base64/Hex/Jailbreak Templates
    单轮、固定变形，成本低，也比较容易被现代模型识别。

  2. Meta/Composite
    使用另一个攻击模型动态修改提示词，持续寻找更容易成功的表达。

  3. Hydra/Crescendo/GOAT
    进行多轮对话、逐步升级、换路线和回退；对有会话记忆的 Agent 更有效，但调用次数和费用明显增加。攻击策略说明

它可以发现“模型或应用接受了危险指令”，但不能证明系统绝对安全。结果仍可能有误判，而且 LLM 输出具有随机性，需要重复测试和人工核查。

危险程度取决于被测系统

被测对象 实际危险程度
普通聊天模型，无工具 较低：主要产生不安全文本或泄露提示词
连接私有知识库的 RAG 中高：可能泄露内部文档或用户信息
连接数据库、邮件、文件的 Agent 高：可能读取或修改真实数据
连接付款、退款、Shell、云服务的 Agent 极高：可能执行真实操作
直接测试生产环境 高：可能产生费用、垃圾数据、工单或真实副作用

所以只能测试自己拥有或明确获得授权的系统；第一次实战应使用本地或测试环境、虚构数据和假密钥。

除了红队攻击还能做什么

Promptfoo还可以：

  • 比较不同模型和不同 Prompt 的质量；

  • 测试准确性、幻觉、格式、延迟和费用；

  • 建立自动 PASS/FAIL 规则；

  • 测试 RAG、Agent、API 和自定义代码；

  • 把失败案例保存为回归测试；

  • 接入 GitHub Actions，在代码或 Prompt 更新时自动检查；

  • 导出 OWASP、NIST、MITRE 等报告；

  • 使用 ModelAudit 扫描 PyTorch、ONNX、SafeTensors、GGUF、Pickle 等模型文件的静态安全风险。ModelAudit 文档

你最适合的实战路线

建议搭建一个故意存在漏洞的“虚拟客服 Agent”：

  • 虚构客户：Alice、Bob；

  • 虚构订单和地址；

  • 放置假秘密：FAKE_SECRET_12345；

  • 提供模拟的查订单、改资料、退款工具；

  • 不接触真实数据库和客户信息。

然后分四轮测试：

  1. Prompt Extraction + Basic：能否套出系统提示词。

  2. System Prompt Override + Base64：能否绕过原始规则。

  3. PII/BOLA/RBAC：能否读取其他虚构客户的数据。

  4. Meta/Hydra：能否通过动态或多轮攻击完成越权退款。

最后加输入过滤、权限校验、工具确认和输出检测，再重新运行，比较修复前后的攻击成功率。这才是完整的实战闭环：

运行
cd ~/promptfoo-redteam-demo
npx promptfoo@latest redteam setup .
替换yaml
npx promptfoo@latest redteam run
–max-concurrency 1
–delay 5000
npx promptfoo@latest redteam report结果
