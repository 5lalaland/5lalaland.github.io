2026-07-21｜OWASP LLM Top 10：从风险分类到测试思路

发表于2026-07-21|更新于2026-10-08|AI Safety
|浏览量:

OWASP LLM Top 10 为大语言模型应用提供了一套面向工程实践的风险地图。它的价值不在于把风险记成十个名词，而在于帮助我们沿着“输入—模型—检索—工具—输出—基础设施”逐层定位攻击面。

1. 十类风险如何理解

风险 典型问题 首要控制点
Prompt Injection 用户或外部文档改变模型行为 指令分层、上下文隔离、输出检查
Sensitive Information Disclosure 泄露提示词、PII、密钥或训练数据 数据最小化、访问控制、脱敏
Supply Chain Vulnerabilities 模型、数据集、依赖包或插件被污染 来源审计、锁定版本、校验哈希
Data and Model Poisoning 训练或知识库中植入错误内容和后门 数据溯源、摄入审核、行为测试
Improper Output Handling 未验证的模型输出进入 SQL、Shell 或网页 结构化输出、参数化调用、编码
Excessive Agency Agent 拥有超出任务需要的权限 最小权限、人工确认、调用审计
System Prompt Leakage 暴露隐藏规则和内部配置 不在提示词中存放秘密、泄露检测
Vector and Embedding Weaknesses RAG 被投毒、越权检索或嵌入反演 ACL、来源可信度、异常检索检测
Misinformation 模型自信地生成错误事实 引用、检索、事实核验和人工复核
Unbounded Consumption 请求泛洪、Token 浪费和 Denial-of-Wallet 限流、长度上限、预算告警

这些风险会叠加。例如，一份含有间接提示注入的文档先进入 RAG，再诱导 Agent 调用高权限工具，最终就同时涉及 Prompt Injection、Vector Weaknesses、Excessive Agency 和 Improper Output Handling。

2. 从分类转成测试用例

我会把每类风险写成四个字段：资产、攻击入口、预期影响和可观察证据。以“过度代理”为例：

  • 资产：修改订单和发送邮件的工具；
  • 入口：用户输入或知识库文档中的恶意指令；
  • 影响：未经确认执行不可逆操作；
  • 证据：工具调用参数、调用身份、审批记录和最终状态。

这样做的好处是，测试结果不会停留在“模型似乎被绕过”，而能回答“哪一个权限边界被突破、造成了什么实际副作用”。

3. 一个适合学习的评测闭环

  1. 搭建只使用虚构数据的测试 Agent，并放置一个假秘密；
  2. 为每类风险准备最小测试集；
  3. 记录输入、模型输出、工具调用和系统状态；
  4. 以攻击成功率、越权率、敏感信息泄露率和误报率汇总；
  5. 加入权限校验、人工确认和输出过滤后重复测试；
  6. 将修复前后的失败案例保存为回归测试。

OWASP 分类提供的是共同语言，真正的安全能力来自可复现的测试证据和持续回归。对我而言，下一步是把 Promptfoo 与 Garak 的结果映射到这十类风险，形成一份可以解释给他人看的评测报告。
