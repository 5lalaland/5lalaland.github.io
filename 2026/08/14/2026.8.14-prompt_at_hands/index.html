2026-08-14｜Prompt Injection 实战：从输入绕过到应用级防御

发表于2026-08-14|更新于2026-10-08|Prompt Injection
|浏览量:

Prompt Injection 的核心不是某个固定字符串，而是攻击者让模型把低可信度内容当成了高优先级指令。评测时，应该同时观察模型文本输出和应用是否执行了不应执行的动作。

1. 三种常见攻击路径

直接注入通过用户消息覆盖任务约束；间接注入把恶意指令放入模型将读取的网页、文档或邮件；多轮攻击则先建立正常对话，再逐步改变任务边界。对 Agent 而言，还需要增加工具注入：恶意内容诱导模型调用读取、写入、发送或删除类工具。

2. 如何设计安全的练习环境

我会使用一个完全虚构的客服 Agent：数据库只包含 Alice 和 Bob 的假订单，环境中放置 FAKE_SECRET_12345，工具仅操作本地测试数据。测试记录至少包括原始输入、上下文来源、模型输出、工具调用参数和最终状态。

测试分为四组：提示词提取、规则覆盖、跨用户访问和高风险工具调用。每组都要有正向用例与负向用例，避免只测攻击成功的场景。

3. 防御要落在应用边界

  • 输入层：做规范化、风险分类和长度限制；
  • 上下文层：把外部数据与高优先级指令明确分隔；
  • 工具层：按用户和任务校验权限，拒绝模型自行扩大权限；
  • 执行层：对退款、删除、发送等不可逆动作要求确认；
  • 输出层：验证结构、敏感信息和下游编码；
  • 监控层：记录攻击链并将失败样本加入回归集。

Instruction hierarchy 和安全微调能提高模型抵抗力，但不应被当作唯一防线。真正决定影响范围的是 Agent 能接触哪些数据、能调用哪些工具，以及每一步是否经过独立授权。
