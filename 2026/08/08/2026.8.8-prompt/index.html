2026-08-08｜Prompt 基础：理解指令层级与上下文边界

发表于2026-08-08|更新于2026-10-08|AI Safety
|浏览量:

Prompt 不是一句“让模型做某事”的话，而是应用把规则、任务、外部数据和用户输入组织在一起的接口。理解这些信息的边界，是分析 Prompt Injection 的起点。

1. 一次请求中有哪些信息

常见的消息角色包括 System、Developer 和 User。它们通常表达不同层级的约束：System 描述应用的总体规则，Developer 描述产品逻辑，User 提供具体任务。实际优先级仍取决于模型和应用的实现，不能把“角色名称”当作可靠的安全边界。

除了消息本身，还要关注上下文窗口、模板变量、历史对话、检索文档和工具返回值。只要这些内容被拼接进模型可见的上下文，就可能影响下一步生成。

2. 常见 Prompt 组件

  • Prompt Template：把固定指令与用户变量组合成稳定格式；
  • Few-shot：用示例约束输出格式和行为；
  • Chain-of-Thought：要求模型展开推理，但不应把内部推理当作安全控制；
  • ReAct：让模型在思考、行动和观察之间循环，常用于工具调用；
  • Context Management：控制历史、检索结果和工具输出进入上下文的方式。

这些技术主要解决可用性问题，并不能单独解决安全问题。比如 Few-shot 示例被污染后，模型可能学会错误的格式；ReAct Agent 还会把错误判断转化为真实工具调用。

3. Prompt Injection 的基本分类

直接注入发生在用户输入中，例如要求模型忽略原始规则。间接注入来自网页、邮件、PDF、代码仓库或 RAG 文档，攻击者不必直接与模型对话，只需影响模型将要读取的内容。进一步还可以出现存储型注入、多轮诱导、工具调用注入和跨模态注入。

输入过滤只能降低一部分风险。改写、多语言、编码混淆和间接注入都可能绕过关键词规则，因此防御必须延伸到权限、上下文隔离、工具确认和输出验证。

4. 一个可执行的安全检查清单

  1. 明确标注系统指令、用户输入和外部数据的来源；
  2. 对外部内容采用“数据而非指令”的处理约定；
  3. 工具调用前验证参数、用户身份和资源权限；
  4. 对高风险动作设置人工确认和幂等保护；
  5. 记录完整的输入、输出和工具调用链；
  6. 用 Direct、Indirect、Multi-turn 三类测试持续回归。

我对 Prompt 的理解也从“如何让模型回答得更好”转向“哪些内容能改变模型行为，以及这种改变是否越过了应用的权限边界”。
